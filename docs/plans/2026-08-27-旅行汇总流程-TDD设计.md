# 旅行汇总流程 TDD 实施计划

> **给执行人员：** 实施时必须按 TDD 执行：先写失败测试，确认失败原因正确，再写最小实现让测试通过，最后再整理代码。

**目标：** “进入下一项”按钮在未选择方案时也可以点击；点击后继续执行后续步骤；景点推荐结束后点击“进入下一项”生成旅行计划汇总页面；已选择模块保持选中且不可切换，未选择模块可继续选择和切换。

**架构设计：** 改动以前端为主。把 `ChatBox.vue` 里的流程判断、默认继续文案、汇总数据构建抽成小的纯函数，先用单元测试固定行为，再接回组件。新增一个 `TripSummary.vue` 汇总组件，展示交通、酒店、景点门票三个模块的候选与选择状态。

**技术栈：** Vue 3、Vite、Vitest、@vue/test-utils、jsdom、现有 FastAPI 选择保存接口。

**现有代码依据：**
- `frontend/src/components/ChatBox.vue` 当前控制“进入下一项”按钮、候选选择和发送下一步上下文。
- `frontend/src/components/TransportCard.vue`、`HotelCard.vue`、`TicketCard.vue` 当前负责三类候选卡片展示。
- `frontend/src/api/agent.js` 已有 `saveTripSelection(tripId, category, item)`。
- `agent-backend/app/agent/core.py` 的系统提示词当前仍要求“选中当前候选并点击进入下一项后”才能继续，需要放宽。

## 全局约束

- 交通、酒店、景点门票任一阶段都不能因为未选择候选而禁用“进入下一项”按钮。
- 未选择候选时，不能调用 `saveTripSelection`，只发送“继续下一项”的上下文。
- 已选择并确认过的模块，在汇总页中必须保持选中状态，并且不能切换。
- 未选择的模块，在汇总页中必须允许选择和切换。
- 不引入路由库；当前应用使用本地 screen/state，汇总页也沿用本地状态。
- 不大面积修复现有乱码文案，避免把业务改动和编码清理混在一起。
- 后端只做最小提示词调整：允许未选择候选也进入下一项，但仍禁止点击前提前搜索后续类别。

- 允许 `selectedTickets` 为空。

汇总数据从历史消息中的三类 cards 构建：

```js
const summarySections = computed(() => [
  {
    key: 'transport',
    title: '交通',
    cards: allCardsByType('transport_offer'),
    selectedIds: confirmedTransportId.value ? [confirmedTransportId.value] : [],
    locked: Boolean(confirmedTransportId.value),
  },
  {
    key: 'hotel',
    title: '酒店',
    cards: allCardsByType('hotel_offer'),
    selectedIds: confirmedHotelId.value ? [confirmedHotelId.value] : [],
    locked: Boolean(confirmedHotelId.value),
  },
  {
    key: 'ticket',
    title: '景点门票',
    cards: allCardsByType('ticket_offer'),
    selectedIds: confirmedTicketIds.value,
    locked: confirmedTicketIds.value.length > 0,
  },
])
```

`handleSummarySelect` 只更新未锁定模块：
- `transport`、`hotel` 单选。
- `ticket` 可先按当前业务保持多选；如果产品要单选，必须另行确认。
